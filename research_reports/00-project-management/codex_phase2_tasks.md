## 二、研究目标与技术口径

### 最终目标

实现卫星星间链路中的严格全光交换：数据 burst 在核心节点保持光信号，并进一步研究控制信息能否避免逐节点 OEO。

### 当前技术判断

1. FDL 是解决光域暂存和输出竞争的基础模块，但 FDL 实现不等于严格全光交换已经实现。
2. 当前独立 BCP 仍在核心节点进行电子处理，控制链路尚未实现全光闭合。
3. 第一篇研究重点是：在 W=1 与载荷可实现延迟器约束下，单级回环 FDL 相对无缓存+重传是否值得加。τ 扫描是证据，不是卖点。
4. 第一阶段边缘调度是受保护的实验基线，其研究价值通过实验 B「是否移动交叉点」体现；光标签等后续功能确有需要时允许受控扩展。实验 C 不进第一篇。

### 关键修正：回环 FDL 与输入 FDL 是两个器件

这是本次修订最重要的一条，它决定实验 C 和阶段四的设计。

现有实现中，burst 要进入 FDL，必须由控制逻辑在 `burstArrival - guardTime/2` 时刻预约 OXC，把入口门连到 FDL 出口门（`OBS_CoreControlLogic.cc:292-305`）。**这个预约本身要求 BCP 提前到达，即 offset > 0。** 当 offset = 0 时 OXC 尚未配置，burst 到达会因为 `schedulingTable[inGate] == -1` 被直接丢弃，回环 FDL 无法介入。

因此必须区分：

| | 回环 FDL（已实现） | 输入 FDL（阶段四需要） |
|---|---|---|
| 位置 | OXC 之后的回环端口 | 每个输入端口上，OXC 之前 |
| 数量 | 每节点 1 条 | 每节点 N 条 |
| 触发 | 有条件（发生冲突时） | 无条件（所有 burst 都经过） |
| 作用 | 解决输出通道竞争 | 补偿标签读取与 OXC 配置时间 |
| 对应问题 | 研究问题 ① ② | 研究问题 ③ |

**结论**：第二层的回环 FDL 工作有效且必要，但它回答的是"竞争缓解"，不能直接证明 `offset→0` 可行。实验 C 必须先建立输入 FDL 的时序模型，再谈可行边界。

### 关键修正：目标口径从 `offset=0` 改为"边缘 offset=0"

严格的 `offset = 0` 在物理上不可达——读标签和配置 OXC 必然消耗时间。可确认的目标口径是：

> **边缘节点发出时 offset = 0**（burst 与控制信息同时出发，不再提前发送独立 BCP），核心节点内部所需的处理时间由**输入端固定延迟线**吸收。

这个口径的好处是 FDL 从"可选的竞争缓解手段"变成"架构的必要组成部分"，且可以在仿真中被证伪。原 `research_status.md` 第七节挂起的两个待确认问题据此可以关闭。

### 可证明性边界

OMNeT++ 只能建模时序，不能证明光标签读取器件的存在性。论文可证明的上限是"数据面严格全光 + 控制面的定量时序预算"；控制面全光作为 future work。**不建议把论文标题绑定在严格全光控制面上。**

### 红线约束

- 保护 `src/EdgeNode/` 的第一阶段基线。与任务无关时不修改；功能确有需要时可扩展，但必须保留原模式语义、默认行为和旧实验可复现性。
- `useFDL=false` 必须与 FDL 开发前保持向后兼容。
- 所有结果必须来自 OMNeT++ 实际仿真。
- W=1，FDL 最多一次回环。
- τ 必须换算为具有卫星载荷可实现性的延迟器参数（最大延迟档、步进粒度、每级插入损耗、开关切换时间）。实际器件是由光开关组成的可调光纤延迟器，不是固定长光纤。
- 不引入缺少实验依据的复杂在线策略。

| 验证点 | 通过标准 |
|---|---|
| 编译 | `make MODE=release` 成功 |
| 直通 | 目标通道空闲时只进行一次 OXC 预约 |
| 回环 | 冲突满足条件时进行两次 OXC 预约，并在 τ 后到达目标输出 |
| 丢弃 | FDL 不可用或等待条件不满足时正确记录竞争丢包 |

| 统计 | FDL/丢包/信道利用率指标可从 `.sca` 提取且口径无重复 |

**已澄清的一处语义**：FDL horizon 更新为 `burstArrival + burstDuration + 3g/4`，未加 τ。这是正确的——FDL 是延迟线不是缓存，多个 burst 只要入口时间不重叠就可以同时在光纤中传播，定长延迟保证出口顺序与间隔不变。horizon 建模的是 FDL **入口占用**。`fdlUtilization` 同理度量入口占用率而非光纤占空比，论文中必须写明这一定义。

### 实验 A：τ 参数扫描

- 主问题：W=1 下，单级回环 FDL 在哪些 τ/T_burst 与负载上有效？这是第一篇 5.1 节的证据，**不是单独卖点**。
- 自变量：**τ/T_burst 比值**（0.25 / 0.5 / 1 / 2 / 4），以及负载、调度器（Horizon / VF）两个维度。
- 计划负载 ρ∈{0.4, 0.6, 0.8}。全互联目前最重点约 0.59；ρ=0.8 必须用 `FDL-Hotspot` 实测后再写入网格，不得把 21.3 µs 标成 ρ=0.8。
- 指标：Burst Loss Rate、均值/95% 时延、FDL 利用率、拒绝原因分解、有效吞吐量。
- 工程输出：τ 与等效光纤长度/延迟器参数的换算区间（`tools/fdl_design.py`）。实际器件是由光开关组成的可调光纤延迟器，其物理约束由最大延迟档、步进粒度、每级插入损耗和开关切换时间决定，而非固定长光纤的 1 km 预算。延迟器档位范围、损耗预算、体积重量需向结构/总体专业确认；D1 冻结后用于第 12 周可行性图。

仿真在 1 Gbps 下进行，物理设计点为 10 Gbps。FDL 动力学只依赖无量纲比值（ρ、τ/T_burst、offset/T_burst），`[Config FDL-RateCheck]` 用于验证该归一化成立。

**RateCheck go/no-go 闸门**（go/no-go 即预设通过/不通过判据的决策闸门，通过才继续投入；判据必须在跑之前定死）：

主判据（稳定量，不受低丢包率放大效应影响）：

- `maxChannelUtilization` 相对偏差 < 10%；
- `fdlUsageCount` 相对偏差 < 15%；
- `carriedBursts` 相对偏差 < 10%。

辅助判据（丢包率，加绝对差兜底——低丢包率下相对偏差天然放大，如 0.1% vs 0.12% 的相对偏差 20% 会触发假 no-go）：

- `burstLossRate` 相对偏差 < 10% **或** 绝对差 < 0.1 个百分点。

go：主判据全部满足 → 按 τ/T_burst 归一化报告。no-go：改为在物理速率下重跑（需开发 burst 级流量源），或降级结论为"仿真速率下成立"。

风险根源：`guardTime`、OXC 切换时间、BCP 处理时延是绝对时间，不随线速率缩放，这正是要验证的东西。

按 4295 B 的 burst 换算到 10 Gbps 设计点：

| τ/T_burst | 物理 τ | 等效光纤长度 | 光纤传输损耗 |
|---|---|---|---|---|
| 0.25 | 0.86 µs | 175 m | 0.04 dB |
| 0.5 | 1.72 µs | 351 m | 0.07 dB |
| 1.0 | 3.44 µs | 701 m | 0.14 dB |
| 2.0 | 6.87 µs | 1402 m | 0.28 dB |
| 4.0 | 13.74 µs | 2805 m | 0.56 dB |

注意：上表的"等效光纤长度"和"光纤传输损耗"是换算参考值。实际器件为**光开关式可调延迟器**，总损耗 = 光纤段损耗 + 级数 × 每级插入损耗（后者通常是主导项）。可行区间上界取决于延迟器的最大延迟档和损耗预算，需向结构/总体专业确认。降低线速率会拉长 burst 时长，从而要求更大的延迟和更多的切换级数。

- 结论边界：实验只证明当前模型和参数范围内的工作区间。

### 实验 C：Offset 缩减

> **2026-09-14：** 移出 16 周主线，进第 17 周起条件阶段。下面技术约束仍有效，只是不再占用第一篇日程。

- 主问题：在输入 FDL 支撑下，边缘 offset 能推进到什么范围？
- 必须先建立输入 FDL 时序模型：`offset_edge = 0` 时，核心节点需要 `t_label + t_OXC` 的处理窗口，由输入 FDL 提供固定延迟 `τ_in ≥ t_label + t_OXC`。
- 必须区分 `offset > 0`、`offset≈0` 和严格 `offset=0`，并明确后者物理上不可达。
- **前置检查**：`params.ini` 中 `BCPProcessingDelay = 0s`、`OEConversionDelay = 0s`、`EOConversionDelay = 0s`。在这些值下 offset 沿路径永不消耗，实验 C 会得到"offset 任意小都可行"的虚假结论。`fdl_params.ini` 已将 `BCPProcessingDelay` 设为 **1 µs（假设值，assumed, to be confirmed against device datasheet）**。实验 C 正式运行前须对 `processingTime` 做敏感性扫描（0.5 / 1 / 5 µs），避免结论依赖单一未验证常数。该值对实验 A/B 几乎无影响，只对实验 C 敏感（每经过一个核心节点 offset 被扣掉一个 `processingTime`）。
- **前置任务：迟到判据崩溃修复**。当前代码 `OBS_CoreControlLogic.cc:150` 的 `burstArrival < simTime()` 为严格小于，`arrivalDelta == 0` 时放行进入正常流程，但第 255 行 `OXCConnectTime = burstArrival - guardTime/2` 会调度到过去时刻，导致 OMNeT++ 运行时崩溃。实验 C 将 offset 往 0 压的扫描中（当扫描点恰为 `processingTime` 整数倍，经足够多跳后剩余 offset 归零），以及第四阶段"边缘 offset=0"场景（第一跳核心节点 `arrivalDelta` 就是 0），都会触发此崩溃。启动实验 C 前须：（1）用 `offset=0` 做一次 smoke 运行实测复现崩溃；（2）将迟到判据改为 `burstArrival < simTime() + guardTime/2` 或在 `scheduleAt` 前加保护。
- 输出应是可行边界和失效原因，而不仅是丢包率曲线。

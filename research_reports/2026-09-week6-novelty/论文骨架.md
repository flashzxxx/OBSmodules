## 0. 主张与边界

**工作题目（定方向，不是定稿）：**  
*Is one stage of optical buffering worth it on single-wavelength inter-satellite links? A payload-constrained evaluation of loopback FDL versus bufferless retransmission in satellite OBS*

**一句话主张：**  
在 W=1 星间链路上，Zhao 2022 与 Roethig/Mouammar 2026 回避星上光缓存，依据是工程直觉而不是量化对照。本文把延迟器的开关时间、插损、档位约束接到网络层性能上，给出单级回环 FDL 相对「无缓存 + 重传」的收益边界，以及边缘调度是否移动这条边界。**结论无论正负都成立。**

这不是「FDL 有没有用」——FDL 排队论已经给出单级定长延迟线的性能上界。本文问的是：在卫星载荷真正装得下的那一级、并且没有波长变换可逃的 W=1 链路上，这一级值不值得加。

## 1. Introduction

论证链：

1. 星间链路希望数据面保持光信号，避免核心节点 OEO。  
2. OBS 是最有希望的体制之一（ADI 2025：星上光缓存可行性未定）。  
3. 现有**卫星** OBS 工作（Zhao 2022；Roethig/Mouammar 2026）一律回避星上缓存，且没有人用数据量化过这个选择。地面 L-OBS 的输入 FDL 是另一条线，不能拿来填这个空。  
4. 研究问题：给定载荷可实现的延迟器，单级光缓存在什么负载、突发长度、调度条件下值得上；越过哪条线该改用重传。

三条贡献：

1. 载荷可行性图：把硬件可实现的 τ 区间叠到丢包曲线上，分出「有用 / 无增益 / 物理不可行」。  
2. 回环 FDL 与「无缓存 + 重传」的交叉点（决策图）。  
3. 边缘四模式是否移动这个交叉点（2×2，压缩成一节，不是主线）。

### 2.1 FDL 竞争缓解与定维（必须补排队论）

地面 OBS+FDL 是经典问题（Chen/Qiao/Yu 2004；ChinaCom 2010 定维实验）。此外还有一整条排队论线，**第 7 周（2026-09-18）已补检索并登记 `refs.bib` 共 10 条**：

- Callegati 2000：变长分组光缓存的粒度；Chlamtac 1996：CORD，延迟线竞争缓解奠基；
- Hunter 1998 SLOB 与 Nizam 1998 WASPNET：FDL 缓存架构；
- **Laevens & Bruneel 2003：单波长光缓存分析；Van Houdt 2004：单波长 FDL 信道利用率与丢包率**；
- Rogiest 2007 退化缓存；Rogiest 2009 同步/异步 FDL 闭式统一模型；
- Lambert 2008：FDL 长度（τ）优化；Lambert 2006：相关到达队列。

**写法（第 6 周口径已修正；第 9 周两篇全文已读）：** 这些解析结果给出了单级 FDL 的性能上界，因此它们关掉的是「再扫一遍 τ 就当贡献」。**但不能再说它们"都假定多波长或全波长变换"**——`laevens2003single` 与 `vanhoudt2004channel` 正是单波长设定，后者还直接给出信道利用率与丢包率，与 5.1 口径重叠。真正剩下的差别是：不含开关插损/切换时间/档位等载荷代价，不在星间场景，且都没有与「无缓存 + 重传」做量化对照。**2026-09-20（第 9 周）两篇全文已取得并读完**（`refs/extracts/laevens2003-infocom-text-2026-09-20.txt`、`refs/extracts/vanhoudt2004-globecom-text-2026-09-20.txt`；精读见 `research_reports/2026-09-week9/文献精读-排队论单波长两篇.md`），写本节时的硬约束有两条：
① **τ/T_burst≈1 属已知的"粒度"结论**——该文给出"最优粒度 D_opt 与 burst 长度分布紧密相关、且依赖负载"，并附一条敏感性结论：**粒度偏离最优点 10%** 时丢包率在最坏情况下可差数个数量级（此 10% 为该文原文给出的数值，非本文仿真结果）；本文 5.1 只能把 τ 选择写成器件模型下的标定，不得写成新发现。
② **两文的 voids 来自 burst 尺寸 mod D**，与第 9 周实测的"同步偏移下 W=1 链路没有任何可补空隙"（VF 补 0 个 burst，附证明）**不是同一件事**，正文必须分开陈述。

## 3. System Model

这一章是新颖性的物理落点。

- **节点架构（图 1）：** Host + Edge + Core；OXC 回环口 `in[N]`/`out[N]` 经延迟 τ 的 FDL 闭合。图 1 可复用 `.doc/` 架构图，须标清回环口位置。  
- **约束与场景：** W=1；单次回环；场景 A 直通 / B 回环 / C 丢弃；BCP 到达偏移 +τ。须写明这是 ChinaCom 意义上的 DO（延迟输出）模式，不是输入 FDL。  
- **调度器：** Horizon 与 Horizon + void filling 两种，作为**实验变量**，不是固定假设。默认仍 Horizon。VF 是对照组，不是第三条 FDL 策略。  
- **载荷延迟器模型（图 2）：** τ 与开关级数、每级插损、切换时间的关系。可行约束写成三条不等式：  
  - τ_min ≥ 开关切换时间；  
  - 累计插损 ≤ 链路功率预算余量；  
  - 级数 ≤ 质量/体积上限。  
  数据源（**2026-09-20 更新：不再依赖 D1 书面回复**）：`research_reports/2026-09-week8/器件参数与三条不等式.md`。
  器件参数取自 Mouammar 2026 TABLE II 及其**原始厂商出处**（Polatis / GLsun / Agiltron 厂商页 + Feyisa 2022 *JLT*），
  表 1 可标「器件手册」而非「假设」。计算结果：τ/T_burst=1 时电光开关需 3 级、总插损 **10.64 dB**；
  InP SOA 同功能仅 **0.14 dB**（但成熟度为实验阶段）。**MEMS 被定量排除**（τ ≥ 8 ms → τ/T_burst ≈ 2.3×10³，而实测最优在 1）。
  唯一仍用假设的是**质量/体积/功耗预算** → 假设 + 敏感性，不阻塞出图。
  ⚠️ 旧默认「每级插损 0.5 dB」过于乐观（Agiltron 实际 3.5 dB/级），`fdl_design.py` 须显式传参。
- **无缓存重传基线：** 核心冲突即丢，源端超时重传，有次数上限。这是 Zhao 路线的最小可比版本。没有它，No-FDL（冲突即丢、不重传）是稻草人。实现放在 host 侧应用层或独立模块，**不改** `src/EdgeNode/`。

### 5.3 载荷可行性图（全文核心图）

把第 3 章硬件可行 τ 区间叠到图 3 上，得到「有用 / 无增益 / 物理不可行」三区（图 6）。审稿人会记住的就是它。

**2026-09-22（第 12 周）初版已成图**：`research_reports/figures/fig6_feasibility.png`（脚本 `tools/plot_fig6_feasibility.py`；器件级联模型直接 import `fdl_design.py`，性能轴直接取第 11 周冻结网格数据，避免图文分叉）。三区数字：

- **有用** τ/T_burst ∈ [0.5, 2]，峰值在 1（ρ≈0.40 时 +6.1 pp、ρ≈0.59 时 +5.2 pp）；τ/T < 0.5 无增益；τ/T > 2 收益衰减，且 ρ≈0.59 下 **τ/T=4 为 −0.9 pp（比不加 FDL 更差）**。
- **物理不可行**：MEMS 需 τ/T ≥ 2328、光束转向 ≥ 7276（比实测最优高 3 个数量级，不等式一定量排除）。对**成熟电光**开关，τ/T ≥ 0.5 的累计插损已 ≥ 10.5 dB（τ/T=1 为 10.64 dB），超出假设的链路余量（10 dB，敏感性 6/10/14）——**"有用"与"付得起"在成熟器件上不重叠**，这就是本节的结论；InP SOA 同功能仅 0.14–0.28 dB（成熟度为实验阶段）。
- **假设项**（表 1 须标注）：链路余量 10 dB、级数上限 6（敏感性 4/6/8）、步进 0.5 µs。若步进取 0.1 µs，电光插损从 10.64 dB 升到 **21.14 dB**（级数 6）——比质量体积更硬的约束，正文应写进不等式二。
- 写作纪律：**不得**把"有用区"说成"可行区"（二者对成熟电光器件不重叠，这正是结论）；**不得**把假设的余量或级数上限当实测值。

### 5.4 边缘调度是否改变答案

2×2（图 7），压缩成一小节，只回答「联合是否移动交叉点」。依赖 Task 1.3 干净基线。不把边缘专利写成主贡献。

**2026-09-22（第 13 周）答案：不移动。** 图 `research_reports/figures/fig7_edge_core_2x2.png`（脚本 `tools/plot_fig7_expB.py`；数据 `results/ExpB-Joint-release` 60 run + `results/ExpR-EdgePair-release` 10 run）。本节以下所有百分数与倍数均由这两个结果目录的 `.sca` 汇总得到（release 构建、repeat 5，`repeat` 见 `attr iterationvars2`），逐格表见 `research_reports/2026-09-week13/分析.md`。要写进正文的三条：

- **交叉点不移动**：同一信道负载水平（ρ≈0.40–0.42）下，回环送达 2241.2 Mbit/s（Static）/ 2519.7（Dynamic），无缓存重传 961.9 / 1125.7 ⇒ **2.33× / 2.24×**。即边缘调度模式只平移绝对损失水平（最高 12.6 pp），不改变「回环优于重传」的相对排序。重传把 ρ 堆到同一水平靠的是 24–33 万次重传副本，有效载荷只有回环的 43% / 45%。
- **本节必须先报四臂公平性**：四臂 burst 长度不同——Static 恒 4295.0 B（等于 `minSizeWithPadding` 下限），Dynamic 4206.5–4210.3 B，最大差 2.1%，不足以解释端到端差距。
- **一处必须写明的口径更正**：第 7 周 Task 1.3 按**核心** burst loss 读得「Static 比 Dynamic 好 0.66–1.52 pp」，端到端口径反过来，Dynamic 好 **5.01–12.59 pp**。原因是 Static 的接入 Dispatcher 在成束之前就恒定丢弃 **14.21–14.27%** 的包（Dynamic 为 0.00%），**核心任何计数器都看不到**；Static 的 burst 更少更大（79.8 µs 下 206,793 束 vs 244,255）故核心失败束数反而更少。**结论写进正文：核心 burst loss 只能作核心内部诊断量，凡「谁更好」一律用端到端口径。**
- 附带换算（可放进本节或 5.2 的脚注）：FDL 的端到端收益 11.2–15.1 pp = 核心读数（4.5–6.2 pp）的 1.9–2.9 倍，因为一个 burst ≈3 个包，再乘边缘存活比例（Static 0.858 / Dynamic 1）；六组数据按 `端到端 = 边缘丢弃 + (1−边缘丢弃) × 网络丢弃` 吻合 ≤0.05 pp。
- 范围限制：重传臂无窗口控制 ⇒ 「交叉点不移动」只在 ρ≈0.40–0.42 得到验证，不得外推到更高负载；14.2% 是本周队列阈值下的常数，阈值扫描列在第 14 周。

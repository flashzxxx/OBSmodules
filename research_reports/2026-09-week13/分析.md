# 第 13 周：实验 B 联合 2×2 与「边缘是否移动交叉点」（2026-09-22）

## 一、本周只回答两个问题

第 7 周 Task 1.3 只看核心 burst loss，第 12 周把 5.4 节的「回环 vs 重传交叉点」留到本周。本
周的问题：

1. 边缘调度模式（Static / Dynamic）与核心 FDL 是否**联合**改变「回环优于重传」这一相对排
   序，即交叉点是否移动？
2. 端到端口径下，FDL 究竟买到多少？

第 12 周约定的验收标准：**只回答交叉点是否移动，不把边缘当第二个主贡献。**

## 二、实验设计

| 批量       | 维度                                                                 | 负载点                  | repeat | run 数 |
| ---------- | -------------------------------------------------------------------- | ----------------------- | ------ | ------ |
| `ExpB-Joint` | 边缘 `dispatchMode` ∈ {Static=3, Dynamic=0} × 核心 FDL ∈ {off, on}    | 79.8 / 35.6 / 21.3 µs   | 5      | 60     |
| `ExpR-EdgePair` | host 侧无缓存重传 × 边缘 `dispatchMode` ∈ {Static, Dynamic}        | 79.8 µs（重传超时 120 ms、上限 3 次） | 5   | 10     |

- 构建：release（`out\gcc-release`）；结果目录带 `-release` 后缀。
- 回环臂的 FDL 延迟 **τ = 34.4 µs**（`fdl_params.ini` 的 `fdlDelayTime`），即 τ/T_burst ≈ **1.00**
  （T_burst = 34.36 µs）。注意 **35.6 µs 是负载点**（`sendInterval`，对应 ρ≈0.40），与 τ 是两个
  不同的量，不得混用。
- 审计（`tools/audit_runs.py`）：0 MISSING / 0 DUPLICATE / 0 STALE，两个批量退出码均为 0。
- 三个负载点对应 `T_burst` = 34.36 µs 的 ρ ≈ 0.20 / 0.40 / 0.59（ρ 为最忙信道实测占用，随
  burst 长度与丢失略有浮动，见下表）。
- 重传超时取 120 ms、重传上限 3 次、`minSizeWithPadding = 64B`（与第 11 周一致）。取 120 ms 而非
  60 ms，是因为 60 ms 对最坏路径（5 跳 × 5 ms 每程）偏紧——实测平均完成时延 69 ms > 60 ms，会大
  量误触发；两个超时值的送达比例相近（80.2% / 81.6%），方向性结论不受影响。
- 两条臂的对照建立在**同一实测信道负载**（ρ ≈ 0.40–0.42）上，而不是同一等待时长：重传臂没有
  FDL，它的 ρ 由重传副本抬高。这一点必须写在正文里，否则会把两种资源的对照误读成同参对照。

三点观察：

1. **边缘丢弃是常数。** Static 在所有 3 档负载、FDL 开与关下丢弃 14.21–14.27%（波动 ≤0.06
   pp），Dynamic 恒为 0.00%。它与核心拥塞无关（FDL 开关不改变它），也不随负载变化。来源指向
   接入侧 Dispatcher 在成束之前的队列阈值；**该机制本周未做阈值扫描验证**，因此正文只能写
   「实测为常数」，不能写成与阈值无关的普适值（阈值扫描列在第 14 周）。
2. **端到端与核心读数方向相反。** 同样负载下 Dynamic 的端到端丢包比 Static 低 5.0–12.6 pp
   （FDL off：9.87 / 7.05 / 5.01 pp；FDL on：12.59 / 8.88 / 5.62 pp，按 79.8 / 35.6 / 21.3
   µs 排列），而核心 burst loss 的方向恰好相反（见第四节）。
3. **burst 长度公平性先报。** Static 恒为 4295.0 B（等于 `minSizeWithPadding` 给出的下限），
   Dynamic 为 4206.5–4210.3 B，四臂最大差 2.1%。两臂 burst 长度确实不同，但这个量级不足以
   解释 5.0–12.6 pp 的端到端差距。

## 四、更正第 7 周 Task 1.3：核心 burst loss 不能单独评价边缘模式

第 7 周 Task 1.3 从**核心** burst loss 得到「Static 比 Dynamic 低约 1.1 pp」（21.3 µs：17.18%
vs 18.71%），本周端到端数据把它反过来：

| 负载   | 核心 burst loss（Static / Dynamic） | 核心口径结论        | 端到端丢包（Static / Dynamic） | 端到端口径结论        |
| ------ | ----------------------------------- | ------------------- | ------------------------------ | --------------------- |
| 79.8 µs | 6.00% / 6.66%                      | Static 好 0.66 pp   | 29.43% / 19.56%                | Dynamic 好 9.87 pp    |
| 35.6 µs | 11.81% / 12.93%                    | Static 好 1.12 pp   | 42.10% / 35.05%                | Dynamic 好 7.05 pp    |
| 21.3 µs | 17.17% / 18.69%                    | Static 好 1.52 pp   | 52.20% / 47.19%                | Dynamic 好 5.01 pp    |

机理（从计数器可直接读出）：Static 的 burst 更少更大（79.8 µs 下发出 206,793 束，Dynamic 为
244,255 束），所以核心看到的失败 burst 数更少；而 Dynamic 的抢占会冲掉部分正在成束的包，反
而抬高核心 burst loss。与此同时，Static 的接入队列阈值在成束之前就把 14.2% 的包丢掉，**这部分
在核心的任何计数器里都不存在**。

结论：评价边缘模式、或评价「边缘 × 核心」联合效果，必须以**端到端送达**为准；核心 burst loss
只能作为核心内部的诊断量。第 7 周 Task 1.3 的结论据此更正。

## 五、为什么端到端 pp 收益是核心读数的 1.9–2.9 倍

FDL 的收益在端到端与核心两侧都能读到，但两者不可互换：

| 边缘    | 负载    | 核心口径 Δ（pp） | 端到端口径 Δ（pp） | 比值  |
| ------- | ------- | ---------------- | ------------------ | ----- |
| Static  | 79.8 µs | 4.54             | 11.24              | 2.48  |
| Static  | 35.6 µs | 6.11             | 13.31              | 2.18  |
| Static  | 21.3 µs | 5.46             | 10.26              | 1.88  |
| Dynamic | 79.8 µs | 4.87             | 13.95              | 2.86  |
| Dynamic | 35.6 µs | 6.16             | 15.13              | 2.46  |
| Dynamic | 21.3 µs | 5.21             | 10.88              | 2.09  |

原因是两层换算，都可以用本周数据核验：

- **一个 burst 约 3 个包**（4295/1400 = 3.07，4207/1400 = 3.00），丢一束带走一整束，所以核
  心 burst 丢失率每 1 pp 在端到端上约值 3 pp。
- **边缘的恒定丢弃给这个收益打折**：端到端 ≈ 边缘丢弃 + (1 − 边缘丢弃) × 网络对存活包的丢弃。
  于是 FDL 的端到端收益 = (1 − 边缘丢弃) × Δ(网络丢弃)，Static 要乘 0.858，Dynamic 乘 1。

按此分解复核六组（网络侧丢弃 = 端到端与边缘丢弃的剥离值）：

| 边缘    | 负载    | 网络丢弃 off → on | Δ 网络丢弃 | (1 − 边缘丢弃) × Δ | 实测端到端 Δ |
| ------- | ------- | ----------------- | ---------- | ------------------ | ------------ |
| Static  | 79.8 µs | 17.73% → 4.57%    | 13.16%     | 11.29 pp           | 11.24 pp     |
| Static  | 35.6 µs | 32.51% → 16.96%   | 15.55%     | 13.34 pp           | 13.31 pp     |
| Static  | 21.3 µs | 44.27% → 32.30%   | 11.97%     | 10.27 pp           | 10.26 pp     |
| Dynamic | 79.8 µs | 19.56% → 5.60%    | 13.96%     | 13.96 pp           | 13.95 pp     |
| Dynamic | 35.6 µs | 35.05% → 19.91%   | 15.14%     | 15.14 pp           | 15.13 pp     |
| Dynamic | 21.3 µs | 47.19% → 36.31%   | 10.88%     | 10.88 pp           | 10.88 pp     |

六组全部吻合到 ≤0.05 pp。另外，「Δ 网络丢弃 ≈ Δ 核心 burst 丢失 × 每 burst 包数」这一近似在
ρ ≈ 0.20 与实测吻合到 ≤0.7 pp，但在 ρ ≈ 0.59 系统性高估 3.6–9.0 pp，说明高负载下被丢的 burst
平均短于总体均值，这个换算不是与负载无关的常数。

## 六、5.4 节的答案：交叉点不移动

数据：`results/ExpR-EdgePair-release`（10 run）。

| 边缘    | 回环（35.6 µs 负载点；τ = 34.4 µs，τ/T_burst ≈ 1.00） | 重传（79.8 µs 请求间隔，超时 120 ms）        | 比值 |
| ------- | --------------------------------------------- | --------------------------------------------- | ---- |
| Static  | 2241.2 Mbit/s @ ρ = 0.4114                    | 961.9 Mbit/s @ ρ = 0.4019                     | 2.33 |
| Dynamic | 2519.7 Mbit/s @ ρ = 0.4571                    | 1125.7 Mbit/s @ ρ = 0.4150                    | 2.24 |

重传臂的细节（说明「同样的信道负载」是怎么来的）：

- Static：请求 244,409，重传 331,006 次，确认 167,482，放弃 48,610；端到端丢包 31.47%，边缘
  另丢 15.75%；ρ 由重传副本堆到 0.4019。
- Dynamic：请求 244,398，重传 241,976 次，确认 195,993，放弃 26,733；端到端丢包 19.81%，边
  缘 0.00%；ρ 堆到 0.4150。
- 即在 ρ ≈ 0.40–0.42 的同一信道负载水平上，重传送出的有效载荷只有回环的 43%（Static）与
  45%（Dynamic）。

结论：两种边缘模式下回环都远高于重传（2.33× / 2.24×），**交叉点不移动**。边缘模式改变的是
绝对损失水平（最高 12.6 pp），不改变「回环优于重传」这一相对排序。按第 12 周验收标准，本周不
把边缘当作第二个主贡献。

## 七、局限与下一周输入

1. 重传臂没有窗口 / 拥塞控制，ρ 只能到 ≈0.42（更高报出负载下失控，见第 11 周记录），所以
   「交叉点不移动」只在 ρ ≈ 0.40–0.42 得到验证，不是全负载区间。
2. 边缘 14.2% 的恒定丢弃来源指向 Dispatcher 队列阈值，本周未做阈值扫描；它是本次全部比较的骨
   架，阈值一改所有曲线整体平移。
3. 图 6 的「有用区」仍不等于「可行区」（成熟电光器件代价不重叠），本周结论不触及该口径。
4. 本周为 release 构建，与第 8 周 debug 批量的方向性结论一致；τ/T_burst = 1 的数值在第 11
   周已复核为逐标量相同。
